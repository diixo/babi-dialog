# Правила аннотирования book-srl

Этот документ описывает текущую разметку в `data/book_srl` и её преобразование в обучающие примеры. Он относится к основному набору `products-book-srl` и дополнительному набору `products-book-srl/annotations`. Правила старых генераторов, включая `build_v4.py`, могут отличаться.

Главный принцип: смысловая разметка, типы участников и границы фрагментов подготовлены заранее в JSON. Во время сборки программа подставляет разрешённых кандидатов, проверяет согласованность данных и записывает вопросы с ответами. Грамматического парсера, автоматического определения сущностей и случайного подбора примеров в этом конвейере нет.

## 1. Источники и запуск

### 1.1. Файлы данных

| Файл | Назначение |
| --- | --- |
| [sentences.json](data/book_srl/sentences.json) | Английские исходные тексты, факты и точные границы фрагментов и глагольных форм |
| [fact_templates.json](data/book_srl/fact_templates.json) | Шаблон каждого исходного примера, его семейство, слоты, ограничения и шаблоны фактов |
| [slot_values.json](data/book_srl/slot_values.json) | Разрешённые значения слотов основного набора, формы слов и сведения об источнике |
| [templates.json](data/book_srl/templates.json) | Дополнительные размеченные шаблоны по урокам; их результат попадает в `annotations` |
| [nouns.json](data/book_srl/nouns.json) | Существительные и участники дополнительной библиотеки |
| [verbs.json](data/book_srl/verbs.json) | Глагольные формы и допустимые объекты дополнительной библиотеки |
| [questions.json](data/book_srl/questions.json) | Заранее составленные человеческие вопросы и ответы к исходным текстам и вариантам |

Markdown и PDF учебника при сборке не читаются. Русские названия уроков и объяснения правил допустимы в метаданных дополнительной библиотеки, но не попадают в английский обучающий текст.

### 1.2. Команды

```shell
python build_book_srl.py
```

Один запуск синхронизирует каталог шаблонов, проверяет все 84 урока и собирает:

- `products-book-srl/{train,valid,test}.txt` — основную SRL-разметку;
- `products-book-srl/questions/{train,valid,test}.txt` — обычные английские вопросы и ответы;
- `products-book-srl/annotations/{train,valid,test}.txt` — дополнительные размеченные шаблоны.

`--library` задаёт каталог исходных JSON, `--out` — каталог результата. `--annotate` включён по умолчанию; `--no-annotate` отключает только дополнительный набор `annotations`. Основной набор и при этом содержит аннотации.

Выбор отдельных уроков, отдельный режим проверки и отдельный запуск синхронизации не нужны: эти действия входят в обычную сборку.

```shell
python build_book_sentences.py
```

Эта команда записывает только английские тексты основного набора в `products-book-srl/sentences.txt`. На каждой строке — один исходный текст или допустимый вариант, без номеров, `User:`, вопросов и ответов. Она проверяет JSON и использует синхронизированный каталог в памяти, но не сохраняет обновлённый каталог шаблонов. Для полной сборки используется `build_book_srl.py`.

## 2. Формат обучающего примера

### 2.1. Story и fragment — разные единицы

**Story** — весь входной текст и его разбор. Вход может содержать одно или несколько предложений. Первая строка всегда имеет вид `1 <исходный текст>`.

**Фрагмент** — текстовая привязка одного факта. Каждому факту соответствует свой блок, начинающийся с `fragment?`. Одно предложение может давать несколько фактов; число точек не определяет число фрагментов.

Пример из дополнительной библиотеки:

```text
1 Mary bought a book. The book is on the table.
2 fragment?	Mary bought a book	1
3 actor?	person	2
4 person?	Mary	2
5 predicate?	bought	2
6 verb?	bought	2
7 action?	buy	2
8 object?	book	2
9 polarity?	positive	1 2
10 type?	non_question	1 2
11 fragment?	The book is on the table	1
12 actor?	book	11
13 predicate?	is	11
14 verb?	is	11
15 action?	be	11
16 where?	on the table	11
17 polarity?	positive	1 11
18 type?	non_question	1 11
```

### 2.2. Нумерация и разделители

Внутри story номера строк последовательны и начинаются с `1`. У вопросов нет индексов фактов: используется `actor?`, а не `actor 1?`.

Строка ответа имеет формат:

```text
<номер> <вопрос><TAB><ответ><TAB><номера опорных строк через пробел>
```

Между тремя частями используется настоящий символ табуляции. Пустая строка отделяет следующую story. Между фрагментами одной story пустых строк нет.

Префиксы `User:` и `Assistant:`, реплики ассистента и вопросы о следующем шаге диалога в этот формат не добавляются.

### 2.3. Порядок вопросов

В каждом блоке порядок такой:

1. `fragment?`;
2. `actor?` и, для типизированного участника, вопрос к его значению;
3. `predicate?`, `verb?`, `action?`;
4. `intention?`, `operation?`, `object?`, если эти значения выводятся;
5. остальные поля факта в порядке их хранения в JSON.

Поле с подчёркиваниями превращается в вопрос с пробелами: `modal_meaning` → `modal meaning?`, `negation_scope` → `negation scope?`. Это технические вопросы к разметке. Человеческие вопросы вроде `Who bought the book?` находятся в отдельном наборе `questions`.

### 2.4. Какие значения скрываются

| Ситуация | Поведение |
| --- | --- |
| Обычное поле равно `none` | Вопрос не выводится |
| `predicate` или `verb` равен `none` | Вопрос выводится: отсутствие формы в тексте существенно |
| Значение равно `unknown` | Вопрос выводится с ответом `unknown` |
| Поле отсутствует в факте | Оно не добавляется автоматически, если это не обязательное поле |
| Поле — `tense`, `aspect`, `voice`, `beneficiary` или `status` | Оно сохраняется в исходной разметке, но не выводится в SRL-вопросы |

Скрытие действует по точному имени поля. Например, `form_voice`, `verb_form`, `completion` или `modal_meaning` не скрываются только потому, что тоже описывают грамматику. Если такое поле присутствует в факте и не равно `none`, оно попадёт в результат.

## 3. Структура исходной разметки

### 3.1. Запись в sentences.json

Файл имеет `schema_version: 1`, список `completed_units` и массив `sentences`. Поля записи:

| Поле | Значение |
| --- | --- |
| `id` | Уникальный стабильный идентификатор примера |
| `unit` | Номер урока от 1 до 84 |
| `text` | Полный английский текст |
| `facts` | Непустой массив смысловых фактов |
| `predicate_spans` | Границы глагольной группы каждого факта |
| `fragment_spans` | Границы текстового фрагмента каждого факта |
| `verb_spans` | Границы основной глагольной формы каждого факта |
| `embedded_roles` | Необязательные связи с отдельно размеченными действиями |

Пример действующей записи:

```json
{
  "id": "u39-e3-04-task",
  "unit": 39,
  "text": "Spring comes after autumn.",
  "facts": [
    {
      "actor": "time",
      "time": "spring",
      "predicate": "comes",
      "action": "come",
      "intention": "none",
      "operation": "none",
      "object": "none",
      "when": "after autumn",
      "tense": "present",
      "aspect": "simple",
      "voice": "active",
      "polarity": "positive",
      "status": "asserted",
      "type": "non_question"
    }
  ],
  "predicate_spans": [
    [
      [
        7,
        12
      ]
    ]
  ],
  "verb_spans": [
    [
      [
        7,
        12
      ]
    ]
  ],
  "fragment_spans": [
    [
      [
        0,
        25
      ]
    ]
  ]
}
```

### 3.2. Обязательные поля факта

При сборке у каждого факта должны быть `actor`, `predicate`, `action`, `intention`, `operation`, `object` и `type`. В существующем корпусе также явно хранятся `polarity` и грамматические метаданные.

Все значения внутри `facts` — непустые английские строки. Даже логические признаки записываются как `yes`/`no`, а неизвестное значение — как строка `unknown`, не JSON `null`. Имена полей имеют форму `[a-z][a-z0-9_]*`.

`fragment` и `verb` не хранятся отдельными строковыми полями факта: они извлекаются из `text` по соответствующим spans. В отличие от них, `predicate` хранится явно и обязательно сверяется с `predicate_spans`.

Список дополнительных полей открыт. Поэтому нельзя добавлять пояснения вроде `note` внутрь факта как обычные строки: генератор начнёт выводить их в качестве вопросов. Описания правил следует размещать в документации или предусмотренных метаданных шаблона.

### 3.3. Индексы и координаты

`facts[i]`, `predicate_spans[i]`, `fragment_spans[i]` и `verb_spans[i]` относятся к одному факту. Число элементов во всех четырёх массивах совпадает.

Каждый диапазон имеет вид `[start, end]`: начало включается, конец не включается. Координаты отсчитываются с нуля в символах Python-строки. Это не байты UTF-8, не номера слов и не координаты UTF-16.

- `fragment_spans[i]` содержит ровно один непустой диапазон.
- `predicate_spans[i]` может содержать несколько диапазонов или быть пустым.
- `verb_spans[i]` тоже может содержать несколько диапазонов или быть пустым в допустимом эллипсисе.
- Части одного списка расположены в порядке текста и не перекрываются между собой.
- Разные факты могут ссылаться на одни и те же символы, например на общий вспомогательный глагол.

Несколько частей `predicate` или `verb` соединяются одним пробелом. Символы внутри каждой части, регистр и апострофы сохраняются.

<a id="actors"></a>

## 4. Участники: actor и четыре категории

### 4.1. Тип и значение разделены

Для размеченных категорий используется пара:

```text
actor?    person
person?   Mary
```

Здесь и в коротких схемах ниже пробелы служат только для выравнивания; в готовом датасете разделителями являются табуляции.

| Значение `actor` | Поле участника | Что оно обозначает |
| --- | --- | --- |
| `person` | `person` | Человек, группа людей или местоимение с человеческим референтом |
| `organization` | `organization` | Организация, учреждение или соответствующий организованный коллектив |
| `location` | `location` | Место, выступающее участником данного факта |
| `time` | `time` | Время, дата или период, выступающий участником данного факта |

В факте с `actor: person` должно быть поле `person`; лишние поля участников `organization`, `location` или `time` в этом же факте не допускаются. Соответствующее поле не может быть пустым или равным `none`, но может быть `unknown`.

`Who wrote this letter?` позволяет установить категорию человека, не устанавливая его личность: `actor: person`, `person: unknown`.

Категория задаётся вручную по смыслу. Генератор не назначает `person` всем словам с заглавной буквы. Например, `The French speak French.` содержит группу людей; в примере, где `Chinese` обозначает язык, это не человек. `Today` в названии газеты не становится временным участником.

### 4.2. Это не разметка всех упоминаний сущностей

Эти четыре поля классифицируют именно участника, хранящегося в `actor`, а не каждое имя или географическое название в предложении.

Если человек работает в организации, нельзя автоматически добавить `organization` рядом с `actor: person` как второй типизированный actor. Связанная организация должна оставаться в подходящей смысловой роли, например `employer`, если именно эта роль предусмотрена разметкой.

Аналогично, `object` может обозначать человека: объект действия не переименовывается в `person` только из-за своей одушевлённости.

### 4.3. Остальные категории пока не введены

Для предметов, животных, событий и неуточнённых участников сохраняется прежняя запись непосредственно в `actor`: `actor: book`, `actor: cat`, `actor: unknown`.

Это текущая смешанная схема: четыре категории уже типизированы, остальные ещё не получили отдельных типов. Нельзя самостоятельно подменять их новыми категориями `thing`, `animal` или `event`, считая такие категории уже согласованными.

`actor: none` означает отсутствие отдельного участника этой роли. Например, в `There is a picture on the wall.` используется `actor: none`, `action: be`, `object: picture`, `where: on the wall`. В выводе `actor?` с `none` отсутствует.

### 4.4. Имена, местоимения и подлежащее

- Имена сохраняют заглавные буквы: `Mary`, `John`, `Kate`.
- Идентификатор словарной записи может оставаться `mary`; это не значение аннотации.
- В обычной внешней реплике `I` нормализуется в `user`, `you` — в `addressee`.
- `he`, `she`, `we`, `they` не заменяются выдуманными именами.
- `they` не всегда означает людей: в `They are pens.` человеческая категория не назначается.
- В прямой речи лицо определяется по доступному контексту говорящего и адресата. Внутреннее `you` не обязано обозначать внешнего `addressee`.

`actor` описывает смыслового участника, а не механически копирует грамматическое подлежащее. В пассиве `The car was repaired by Mary.` это `actor: person`, `person: Mary`, `object: car`. Неуказанный исполнитель пассива остаётся неизвестным; его нельзя заимствовать из соседнего упражнения.

### 4.5. Time/location и when/where

`time` и `location` теперь зарезервированы для значений типизированного участника. Обстоятельства хранятся в `when` и `where`.

| Пример | Участник | Обстоятельство |
| --- | --- | --- |
| `Spring comes after autumn.` | `actor: time`, `time: spring` | `when: after autumn` |
| `When is your birthday?` | `actor: time`, `time: your birthday` | `when: unknown` |
| `Newcastle is a large city in the north-east of England.` | `actor: location`, `location: Newcastle` | `where: in the north-east of England` |
| `The book is on the table.` | `actor: book` | `where: on the table` |

Смена этих имён не объединяет все пространственные и временные отношения. `destination`, `source`, `duration`, `frequency`, `since` и другие уже существующие роли сохраняют собственный смысл.

## 5. Predicate, verb и action

### 5.1. Три разных представления

| Поле | Смысл | Пример |
| --- | --- | --- |
| `predicate` | Глагольная группа в исходной форме, включая выбранные вспомогательные слова и отрицание | `has been reading` |
| `verb` | Основная глагольная форма, действительно присутствующая в тексте | `reading` |
| `action` | Нормализованное действие или отношение | `read` |

`predicate` и `verb` подтверждаются точными координатами. `action` берётся из ручной разметки или согласованной подстановки, а не вычисляется лемматизатором во время сборки.

### 5.2. Связки и формы be

`is`, `are`, `was`, `'s` и другие формы сохраняются в `predicate` и `verb`, когда они являются основной глагольной формой факта. В `action` используется `be`.

В конструкции `There is ...` тоже используется `be`, а не `exist`. `exist` соответствует собственному глаголу `exist`, например в `has existed`.

Смысловое свойство связки хранится в `complement`, место — в `where`. Из `Mary is happy.` не создаётся вымышленный прямой объект `happy`.

### 5.3. Сокращения и совпадающие слова

Апострофы и сокращения не раскрываются в поверхностных полях: `She's been sleeping` → `predicate: 's been sleeping`, `verb: sleeping`, `action: sleep`.

Одинаковая запись `'s` может обозначать `is` или `has`; `'d` — `had` или `would`. Различие уже должно быть отражено в разметке. Притяжательное `'s` в имени не становится глаголом только из-за совпадения символов.

Повторяющиеся `is`, `to pay` и другие формы различаются по координатам. Поиск первого совпавшего слова вместо хранения spans недопустим.

### 5.4. Вопросы и разрыв глагольной группы

В `Have you seen them?` группа состоит из частей `Have` и `seen`: `predicate: Have seen`, `verb: seen`, `action: see`. Подлежащее `you` не попадает в `predicate`.

В `does it take` получается `predicate: does take`, `verb: take`. В `has already written` обычное наречие не включается в глагольную группу: `predicate: has written`.

### 5.5. Фразовые глаголы и глаголы с предлогом

Частицы, входящие в размеченное действие, сохраняются в поверхностной и нормализованной формах:

| Текст | `verb` | `action` |
| --- | --- | --- |
| `turned it off` | `turned off` | `turn off` |
| `hit back` | `hit back` | `hit back` |
| `phoned back` | `phoned back` | `phone back` |
| `go out to lunch` | `go out` | `go out` |
| `is searching for` | `searching for` | `search for` |
| `relies on` | `relies on` | `rely on` |
| `depends on` | `depends on` | `depend on` |
| `was listened to` | `listened to` | `listen to` |
| `looks forward to` в соответствующем дополнительном шаблоне | `looks forward to` | `look forward to` |

В разделённом `turned it off` объект `it` остаётся вне глагольной формы; для `verb` выбираются два диапазона.

`predicate` тоже сохраняет эти части: `was listened to`, `has to rely on`, `do wait for`. Вопросительный порядок, пассив и модальный глагол не меняют нормализованное действие: `Who is she waiting for?` → `predicate: is waiting for`, `verb: waiting for`, `action: wait for`, `object: unknown`.

Объект выбранной предложной конструкции записывается в `object`, если поле свободно. Это смысловая роль, поэтому она может обозначать человека: `relies on Anna` → `object: Anna`. Например, прежний `target` у `look at` или `wait for` и прежний `recipient` у `speak to` занимают свободный `object`. Уже заполненный объект сохраняется: у `What is this book devoted to?` остаются `object: this book` и `target: unknown`, а действие — `devote to`.

Если аргумент выражен отдельным действием, он сохраняет свой фрагмент. В `Why do you insist on leaving?` это `Why do you insist on` и `leaving`: предлог `on` принадлежит `insist on`. Существующая связь `embedded_roles` скрывает развёрнутый `content` родителя в выводе. Аналогично у `You never listen to what I say.` вложенный `what I say` не дублируется значением `object?` в первом блоке.

Между глаголом и предлогом могут стоять другие слова. В `She listened for a few moments to a Chopin prelude` получаются `predicate: listened to`, `verb: listened to`, `action: listen to`, `object: Chopin prelude`, `duration: a few moments`. Координаты выбирают две части; длительность не становится частью глагола. В `Who do you always wait here for at this time?` поле `verb` содержит `wait for`, а `here` остаётся в `where`.

Не каждый соседний предлог входит в действие. Решение принимается для конкретной конструкции, а не по списку слов:

| Контраст | Разметка |
| --- | --- |
| `wait for a bus` / `wait for an hour` | `action: wait for`, `object: bus` / `action: wait`, `duration: an hour` |
| `come in` / `come in time` | `action: come in` / `action: come`, `when: in time` |
| `look at the sky` / `look out of the window` | `action: look at`, `object: sky` / `action: look`, `direction: out of the window` |
| `agree to an offer` / `agree to help` | `action: agree to` с объектом / `agree` и отдельный инфинитив `to help` |
| `ask for advice` / `ask somebody for advice` | Предложная конструкция `ask for` / возможная переходная конструкция `ask` с адресатом и содержанием просьбы; разметка зависит от явно выбранной структуры |

Семьи с `listen to`, `look at`, `wait for`, `belong to`, `agree with/on`, `think about/of`, `talk about/to`, `speak about/to/with`, `insist on`, `object to` и другими размеченными конструкциями используют одинаковое правило сохранения предлога. Обычные обстоятельства места, времени и способа действия сохраняют отдельные роли.

`search for`, `rely on`, `depend on` дополнительно представлены в синтетической библиотеке. Их формы хранятся целиком в `verbs.json`: например, `rely on`, `relies on`, `relied on`, `relying on`. Добавление синтетического шаблона не добавляет вымышленное предложение в исходный корпус книги.

### 5.6. Эллипсис

| Случай | `predicate` | `verb` | `action` |
| --- | --- | --- | --- |
| Отсутствующая связка в `The more beautiful the picture ...` | `none` | `none` | `be`, если это явно размеченное отношение |
| Оставшийся инфинитивный маркер в `... I'd like her to.` | `to` | `none` | Действие из доступного контекста, например `treat` |
| Самостоятельное `Yes, she does.` без названного действия | `does` | `does` | `unknown` |
| Самостоятельное `So were we.` | `were` | `were` | `unknown` |
| `Children like singing and often do it badly.` — второй факт | `do` | `do` | `sing` |

Сохранившуюся форму нельзя заменять отсутствующим словом. Нормализованный смысл при этом может отличаться от поверхностного глагола.

Пустой `verb_spans` допустим при `predicate: none`, `to`, `not to` или `to not`. Если глагольная форма сохранена, у неё должна быть текстовая привязка.

Исключение сохраняется и для многословного действия: в `... promised to call on him ... failed to do it` поверхностное `verb: do` не подменяется отсутствующим `call on`. У `worn-out` сохраняется дефис исходного текста, хотя нормализованное действие — `wear out`.

### 5.7. Модальные и составные глагольные формы

Модальная конструкция относится к основному действию. Она входит в `predicate`, но не включается в `verb` и `action` этого действия и не получает дополнительный фрагмент только из-за наличия вспомогательного слова.

| Текст глагольной группы | `predicate` | `verb` | `action` | Дополнительные поля |
| --- | --- | --- | --- | --- |
| `has to finish` | `has to finish` | `finish` | `finish` | `modality: have to` |
| `must have been waiting for` | `must have been waiting for` | `waiting for` | `wait for` | `modality: must` |
| `hasn't been able to work` | `hasn't been able to work` | `work` | `work` | `modality: be able to`, `polarity: negative` |
| `might be able to do` | `might be able to do` | `do` | `do` | `modality: might`, `ability: be able to` |
| `is likely to pass` | `is likely to pass` | `pass` | `pass` | `modality: be likely to` |
| `'d rather go` | `'d rather go` | `go` | `go` | `modality: would rather` |
| `needs to rest` | `needs to rest` | `rest` | `rest` | `modality: need to` |

То же разграничение применяется к `can`, `could`, `may`, `might`, `must`, `should`, `would`, `shall`, модальным `need` и `dare`, а также `be to`, `be going to`, `used to`, `had better`, `be supposed to`, `be unlikely to`. Компоненты `likely`, `unlikely`, `rather`, `better` сохраняются как часть конструкции, а не удаляются как обычные наречия.

Имена конструкций в `modality` и `ability` пишутся с пробелами: `have to`, `be able to`, `be going to`. Это одинаково для основного корпуса и дополнительного набора `annotations`.

Отрицание не меняет лексическое действие. Отсутствие необходимости в `does not have to work` и запрет в `must not work` различаются модальностью и областью отрицания, когда она явно размечена. Нельзя выводить из обоих примеров, что работа фактически не состоялась. `need not have bought` также не равнозначно `did not buy`.

Наличие слова `have` или `need` само по себе не делает конструкцию модальной: `has a book` → `action: have`, `needs advice` → `action: need`. В `How much sugar do you need to make this cake?` у `need` есть объект `sugar`, а `to make this cake` — отдельное действие. Это отличается от `needs to rest`, где необходимость относится непосредственно к `rest`.

Слоты шаблона должны менять согласованно текст, поверхностную форму, нормализованное действие и модальность. Для целой формы `{v.gerund}` подставляется, например, `searching for`; для разнесённого `turned it off` требуются отдельные привязки к основной форме и частице. `expand_predicates` переносит координаты при подстановках, а проверка применяется к каждому полученному варианту. Исправление только `sentences.json` без соответствующего `fact_templates.json` не считается завершённым.

## 6. Правила фрагментации

### 6.1. Сначала смысл, затем границы

При ручной разметке сначала определяют факты, их участников и смысловые роли. Затем каждому факту назначают один непрерывный участок исходного текста, позволяющий привязать этот факт к конкретной конструкции.

Фрагмент не обязан быть самостоятельным грамматическим предложением. В нём могут отсутствовать общий субъект, вспомогательный глагол или сравниваемый объект. Такие сведения используют полный контекст story.

Нельзя строить фрагмент как пересказ или вставлять в него восстановленные слова. `fragment?` всегда возвращает точную подстроку исходного `text`.

### 6.2. Сочинение

В `Yes, he is, but he is taller and seems much stronger than Paul.` размечены три факта:

| Фрагмент | `predicate` / `verb` | `action` | Существенные роли |
| --- | --- | --- | --- |
| `Yes, he is` | `is` / `is` | `be` | `person: he`, `complement: unknown` |
| `he is taller` | `is` / `is` | `be` | `complement: taller`, `comparison: Paul` из полного текста |
| `seems much stronger than Paul` | `seems` / `seems` | `seem` | `person: he` из контекста, `complement: stronger`, `intensity: much` |

Не следует подставлять `taller` в первый факт: это краткое подтверждение с неизвестным свойством. Общий `Paul` и опущенный во втором сказуемом субъект сохраняются в ролях, но не дописываются внутрь фрагмента.

### 6.3. Инфинитивы, герундии и вложенные конструкции

Отдельное смысловое действие получает собственный факт, если оно так представлено в выбранной схеме данного примера. Типичные случаи — инфинитивное дополнение, герундий, относительное или обстоятельственное предложение.

Например, `How long does it take you to water all these flowers?` разделяется на `How long does it take you` и `to water all these flowers`. Вторая часть не должна начинаться с искусственно присоединённого `you`, если этот текст уже принадлежит основной конструкции.

Это не универсальное правило «один глагольный токен — один факт». Вспомогательные формы составляют один `predicate`; некоторые намерения в основном корпусе свёрнуты в целевое действие. Эти случаи описаны ниже.

### 6.4. Перекрытия допустимы

Фрагменты не образуют обязательное разбиение на непересекающиеся куски. Если цельный субъект или дополнение содержит вложенную конструкцию, внешний факт может охватывать её целиком:

| Текст | Сохранённые фрагменты |
| --- | --- |
| `The computer I have is very slow.` | `The computer I have is very slow`; `I have` |
| `Going there by car is very convenient.` | `Going there by car is very convenient`; `Going there by car` |
| `To know everything is to know nothing.` | Полная конструкция; `To know everything`; `to know nothing` |
| `Which ballet do you think is better?` | `do you think`; `Which ballet do you think is better` |

Здесь перекрытие сохраняет непрерывность исходной фразы. Нельзя склеивать удалённые куски в новый «фрагмент» с пропущенной серединой: разрыв допускается в `predicate_spans` и `verb_spans`, но не в одном `fragment_spans[i]`.

Отсутствует и требование покрыть каждым набором фрагментов все союзы и знаки препинания. Границы задаются разметкой; генератор не отрезает финальную пунктуацию по единому правилу.

### 6.5. Общие глагольные элементы

В `I'll arrive ..., leave ..., and then take ...` группы могут иметь вид `'ll arrive`, `'ll leave`, `'ll take`, хотя `'ll` написано один раз.

Каждая часть предиката должна находиться либо внутри собственного фрагмента, либо в другом фрагменте, где она явно представлена в предикате. Простого копирования одинаковых координат недостаточно, если ни один фрагмент не содержит исходную часть.

Если собственная основная форма находится внутри фрагмента, фрагмент должен включать и все части её `verb`, в том числе отделённую частицу. Для унаследованной основной формы допускается явная общая привязка с другим фактом.

### 6.6. Порядок фактов

Основной набор выводит факты в порядке массива `facts`. Этот порядок не обязан совпадать с возрастанием начала каждого фрагмента: внешний факт может предшествовать вложенному.

В дополнительном наборе `annotations` факты каждого предложения перед выводом сортируются по началу фрагмента. Исходный порядок `predicates` остаётся значимым для метаданных `parent`; связи `embedded_roles` при перестановке пересчитываются.

Нельзя переставлять только один массив spans или только факты: их индексы должны изменяться согласованно.

<a id="roles"></a>

## 7. Смысловые роли

### 7.1. Объект, свойство и содержание

| Поле | Назначение |
| --- | --- |
| `object` | Объект действия; в пассиве обычно участник, над которым совершается действие |
| `complement` | Предикативное свойство, состояние, профессия или идентификация после связки |
| `content` | Содержание мысли, сообщения или другого отношения, если оно предусмотрено разметкой |
| `recipient` | Получатель передачи, сообщения или распоряжения |
| `target` | Цель направленного действия или отношения в принятой для конструкции схеме |
| `topic` | Тема речи, мысли или отношения |
| `experiencer` | Тот, кто переживает состояние или для кого оценивается ситуация, когда эта роль выделена |
| `possessor` / `owner` | Обладатель или владелец в соответствующем шаблоне |

`object` и `content` не являются взаимозаменяемыми контейнерами для любого текста. Для существующей семьи нужно сохранять принятое распределение. Если роль обозначает отдельное действие, её длинное значение может быть скрыто через `embedded_roles`, но не удалено из исходного факта.

Нельзя заменять именной объект длинным содержанием соседней клаузы только ради заполнения поля. В то же время объект вроде `clothes made of leather` остаётся именной группой и сам по себе не требует скрытия.

### 7.2. Пространство, время и дополнительные отношения

| Группа | Поля и смысл |
| --- | --- |
| Место и перемещение | `where` — где; `destination` — куда; `source` — откуда; `path` — путь; `direction` — направление |
| Время | `when` — когда; `duration` — длительность; `frequency` — частота; `since` — исходная граница, если выделена отдельно |
| Причина и условия | `reason`, `cause`, `condition`, `concession`, `circumstance` — отношения, явно предусмотренные фактом |
| Способ и средства | `manner`, `means`, `method`, `instrument`, `transport`, `medium` |
| Сравнение | `comparison` — с чем/кем сравнивают; `degree` — степень; `intensity` — усиление; `difference`, `extent` — другие параметры |
| Количество | `quantity`, `amount`, `price`, `distance`, `age` и другие специализированные значения |
| Совместность | `companion`, `accompaniment`, `reciprocal` |
| Дополнительное описание | `attribute`, `material`, `language`, `origin` и другие роли конкретного примера |

Это ориентир по существующим полям, а не закрытый универсальный набор SRL-ролей. Наличие роли должно следовать из исходного текста и принятого разбора; не нужно заполнять все колонки для каждого факта.

Предлоги сохраняются там, где они входят в значение роли: например, `where: on the table`. При этом значения участников и объектов могут быть нормализованы: `The book` → `book`. Единого правила «удалить все артикли и предлоги» нет.

### 7.3. Возвратность и усиление

В `I hurt myself.` используются `person: user`, `object: user`, `reflexive: yes`. Совпадение записывается по нормализованному участнику, а не по буквальному `myself`.

Возвратная форма может занимать другую роль: `Jane looked at herself ...` связывает `target` с `Jane`; `He made himself a cup of tea.` — `beneficiary` с `he`. Последнее поле хранится в JSON, но скрыто в обучающем выводе.

Усилительное `You yourself told us the story.` не превращает `story` в возвратный объект: используются `emphasis: person`, `reflexive: no`. `by himself` может обозначать самостоятельность, а `each other` — взаимность. Эти конструкции нельзя объединять одним правилом замены местоимения.

### 7.4. Purpose больше не используется

Приняты три правила:

1. Именную цель можно поместить в свободный `object`, если это естественно в данной конструкции.
2. Цель, выраженную отдельным действием, разбирают отдельным фактом и фрагментом.
3. Уже существующий объект, включая `unknown`, сохраняют при конфликте.

Например, `go out to lunch` получает `action: go out`, `object: lunch`. В `I want to give him a book as a present.` объектом остаётся `book`.

`purpose` как поле, `syntactic_function: purpose` и соответствующая связь `relation: purpose` в дополнительной библиотеке запрещены. Отдельные фрагменты сами по себе не кодируют связь «это действие является целью другого» — такую связь текущий компактный вывод не восстанавливает.

## 8. Вопросительность, отрицание и неизвестные значения

### 8.1. Type

`type` обязателен и имеет ровно два значения:

- `question` — вопросительная форма реплики;
- `non_question` — невопросительная форма.

Он задаётся явно для каждого факта. Генератор не определяет его по последнему символу текста.

`Could you answer my question?` остаётся `question`, хотя по смыслу это просьба. Команда без вопросительной формы — `non_question`. У вложенных действий вопроса тоже может быть `type: question`: это не означает, что каждое такое действие образует отдельный самостоятельный вопрос.

Прямая речь может сочетать `non_question` у слов автора и `question` у цитируемого вопроса. Косвенный вопрос внутри повествования, например `I wonder if he is home.`, остаётся `non_question`.

Условие с `if` не создаёт третьего значения `type`. Для него существует `condition` и соответствующая смысловая разметка. `if` со значением «ли» нельзя автоматически считать условием.

### 8.2. Polarity и область отрицания

В текущем корпусе `polarity` имеет значения `positive` и `negative`. Это полярность размеченного события, а не механическая проверка наличия `not` в полном тексте.

Отрицание в одной клаузе не переносится на соседнюю. Отрицательные местоимения и наречия могут выражать отрицание без отдельного `not`. Отсутствие обязанности не равняется утверждению, что действие не произошло.

Если это предусмотрено примером, `negation_scope`, `modal_meaning`, `outcome`, `continuation` и другие поля уточняют область отрицания, модальность и результат.

### 8.3. None и unknown

`none` означает отсутствие данной роли или формы. `unknown` означает, что роль или действие есть, но конкретное значение нельзя установить из доступного входа.

Примеры:

- у `There is ...` отдельного actor нет: `actor: none`;
- неизвестный исполнитель пассива: `actor: unknown`;
- неизвестный человек в вопросе `Who ...?`: `actor: person`, `person: unknown`;
- в отдельном `Yes, she does.` действие неизвестно: `action: unknown`;
- при пропущенной связке поверхностной формы нет: `predicate: none`, `verb: none`.

Нельзя заполнять `unknown` ответом из следующего примера, печатных ключей или соседней story, если этот ответ не входит в текущий входной текст.

### 8.4. Intention, operation и status

В основной библиотеке явно выраженное текущее положительное намерение может быть свёрнуто в целевое действие. Для `I want to give him a book as a present.` хранится один факт: `predicate: to give`, `action: give`, `intention: give`, `operation: add`.

Это соглашение конкретных аннотаций, а не автоматическое правило генератора для каждого `want`. Прошлое желание, чужое намерение, отрицание и сообщение о чьём-то распоряжении нельзя автоматически превращать в добавление текущего намерения.

Допустимые значения `operation`: `none`, `add`, `remove`, `replace`, `keep`, `clear`, `complete`. Поле описывает смысловую операцию с намерением, а не время глагола и не действие программы над внешним приложением. В текущих исходных фактах книги используются `none` и `add`.

`status` описывает состояние события: например, `asserted`, `reported`, `intended`, `hypothetical`, `counterfactual`. Это отдельная ось, отличная от `type` и `polarity`. Значение `questioned` удалено и запрещено; вместо него сохраняется явный `type`, а отсутствующий `status` не заменяется автоматически на `asserted`.

`status`, `tense`, `aspect` и `voice` остаются в данных для сохранения разбора, хотя соответствующие вопросы сейчас скрыты. Отсутствие этих вопросов в датасете не означает, что различия событий автоматически выведены из других полей.

<a id="embedded"></a>

## 9. Вложенные действия и embedded_roles

### 9.1. Зачем нужна связь

Некоторые значения `actor`, `content` или `object` обозначают целое действие, которое уже разобрано отдельным фактом. Повторять его длинным ответом в родительском блоке не требуется.

В исходном JSON значение сохраняется, а `embedded_roles` указывает, какой отдельный факт его представляет:

```json
{
  "embedded_roles": {
    "0": {
      "actor": [1]
    }
  }
}
```

Это означает: у факта с индексом `0` роль `actor` представлена фактом с индексом `1`; при выводе этой роли в родительском блоке не будет.

Ключи источников — строки с десятичными индексами, значения ссылок — массивы целых индексов. Оба вида индексов начинаются с нуля. Это индексы фактов, не номера строк итогового датасета.

### 9.2. Take time

У `How long does it take you to water all these flowers?` исходный actor отношения `take` — событие `watering all these flowers`. Это не человек. Оно связано с отдельным фактом `water`, поэтому длинный `actor? watering ...` в первом блоке скрывается.

Человек относится к действию `water`; в первой части также остаётся `experiencer: addressee`.

```text
1 How long does it take you to water all these flowers?
2 fragment?	How long does it take you	1
3 predicate?	does take	2
4 verb?	take	2
5 action?	take	2
6 object?	time	1 2
7 duration?	unknown	2
8 experiencer?	addressee	1 2
9 polarity?	positive	1 2
10 type?	question	1 2
11 fragment?	to water all these flowers	1
12 actor?	person	1 11
13 person?	addressee	1 11
14 predicate?	to water	11
15 verb?	water	11
16 action?	water	11
17 object?	all these flowers	11
18 polarity?	positive	1 11
19 type?	question	1 11
```

### 9.3. Ограничения связи

Разрешены только связанные роли `actor`, `content` и `object`. Цели должны существовать, отличаться от исходного факта и не повторяться. Связанная роль не может отсутствовать или иметь значение `none`/`unknown`. У цели должен быть другой фрагмент, а не тот же самый диапазон.

Рендерер следует явной связи. Совпадение глаголов или похожее содержимое строк не создаёт `embedded_roles` автоматически. Если связь убрать, исходное значение роли снова начнёт выводиться.

Связь не должна скрывать именные объекты, свойства или неразобранные ожидания. Содержательная правильность ссылки требует ручной проверки: существование целевого индекса само по себе не доказывает правильную семантику.

<a id="evidence"></a>

## 10. Ссылки на доказательства в тексте

### 10.1. Два уровня контекста

`fragment?` всегда ссылается на строку `1`.

Остальные вопросы ссылаются:

- на строку текущего `fragment?`, если выбранного фрагмента достаточно по правилам рендерера;
- на `1` и строку текущего `fragment?`, если нужны сведения из полного входа.

Они не образуют цепочку ссылок на предыдущие ответы `actor?`, `action?` и т. п. Строка с фрагментом служит локальной опорой; строка `1` — общим контекстом, включая соседние предложения той же story.

### 10.2. Правила текущего рендерера

| Вид ответа | Как выбирается опора |
| --- | --- |
| `type` | Всегда полный вход и фрагмент: нужна форма реплики и её контекст |
| `predicate` | Локальная опора, если его части входят во фрагмент; для общих частей вне фрагмента добавляется строка `1` |
| `verb` | Аналогичная проверка его spans |
| `action` | Учитывается наличие основной формы и локальность предиката; восстановленный смысл эллиптического `do` и подобных форм может требовать полного входа |
| Тип actor и его значение | Одинаковая опора, вычисленная по самому участнику, а не по слову `person`/`organization` |
| `unknown` | Для роли проверяются соответствующие вопросительные слова, в том числе вынесенные за границы фрагмента |
| Обычная роль | Учитывается присутствие значения в фрагменте; для `user`/`addressee` в роли участника используются поверхностные `I`/`you` |
| Контекстный признак | У изолированного фрагмента может понадобиться строка `1`, даже если ответ — короткая метка |

Если фрагмент охватывает весь вход, за исключением учитываемой рендерером внешней пунктуации и пробелов, он обычно достаточен сам по себе. `type` всё равно сохраняет ссылку на строку `1`.

Контекстные признаки в коде перечислены явно: `intention`, `operation`, `polarity`, `type`, `verb_form`, `form`, `participle_form`, `form_voice`, `degree`, `syntactic_function`, `modality`, `modal_meaning`, `negation_scope`.

### 10.3. Пределы доказательности

Это правила формирования ссылок, а не универсальный логический доказатель. Совпадение строки роли с текстом ещё не доказывает верный выбор участника; отсутствие буквального совпадения не обязательно означает ошибку нормализации.

Для `unknown` текущая эвристика работает по спискам вопросительных слов для каждой роли, а не по полноценному синтаксическому разбору. Если она не найдёт вынесенного подходящего слова, ответ может остаться с локальной опорой. Спорные случаи нужно проверять на уровне конкретного примера.

<a id="templates"></a>

## 11. Шаблоны и кандидаты

### 11.1. Одни подстановки для текста и фактов

Каждая исходная запись основного корпуса имеет шаблон. Его `original` выбирает такие значения слотов, которые должны точно восстановить исходный текст, факты и spans.

Пример связанного фрагмента шаблона:

```text
{actor_frame.word_subject}{actor_frame.word_auxiliary} {verb.word} an interesting {noun_1.word}.

actor: person
person: {actor_frame.actor}
predicate: {actor_frame.word_auxiliary} {verb.word}
action: {verb.lemma}
object: interesting {noun_1.word}
```

Нельзя независимо менять текст и ответы. Подстановка, меняющая `I` на `she`, должна одновременно менять форму вспомогательного глагола и значение `person`, если это предусмотрено данным шаблоном.

### 11.2. Границы в строке шаблона

Spans шаблона считаются по его исходной строке, включая символы `{placeholder}`. При раскрытии слотов программа пересчитывает границы по длине подстановок.

Граница может охватывать placeholder целиком, но не разрезать его. Поэтому субъект и сокращённый вспомогательный глагол при необходимости должны храниться отдельными атрибутами слота.

Явно предусмотренный необязательный placeholder может раскрыться в пустую строку. Выбранный целиком диапазон такого placeholder исчезнет. Произвольное исчезновение группы из нескольких частей этим правилом не разрешается: итоговые spans всё равно проходят проверку.

### 11.3. Смысловая и грамматическая совместимость

Варианты должны сохранять:

- грамматическое согласование лица, числа и глагольной формы;
- форму местоимения и соответствующего `self`/`selves`;
- совместимость артикля с существительным;
- смысловую совместимость глагола, объекта и модификаторов;
- категорию участника и наличие правильного поля со значением;
- привязку всех изменяемых ролей к одним и тем же кандидатам.

Основная библиотека использует явно разрешённые пары `constraints`. Дополнительная — в том числе список допустимых объектов глагола через `compatible`.

Само нахождение слов в книге не означает, что их можно произвольно комбинировать. Например, наличие `write` и `magazine` в словарях не разрешает такой вариант в семье, где допустимы только другие объекты.

### 11.4. Категории кандидатов не должны смешиваться

Если один шаблон подставляет и `children`, и `cities`, нельзя присвоить всем вариантам `actor: person`.

В дополнительной библиотеке шаблон множественного числа разделён на варианты для людей, мест и остальных существительных. Они сохраняют общее семейство `u11_plural_agreement`, чтобы связанные подстановки не разошлись между выборками.

Это явное решение в JSON. Генератор не переклассифицирует кандидата по окончанию слова или заглавной букве.

### 11.5. Допустимый синтаксис подстановок

Поддерживается доступ по ключам словарей: `{slot}` или `{slot.attribute}` с допустимыми именами компонентов. Конечное значение должно быть строкой или целым числом, но не `bool`.

Вызовы, `eval`, Python-доступ к атрибутам объектов, форматирующие спецификаторы и преобразования вроде `{value!r}` не поддерживаются. Неизвестный ключ вызывает ошибку.

## 12. Особенности дополнительной библиотеки annotations

### 12.1. Другая структура источника, тот же выходной формат

Дополнительный шаблон содержит `id`, `source: unit-N`, `rule`, `slots` и массив `sentences`. У каждого предложения есть `text`, `predicates`, spans и необязательные метаданные.

У predicate-события обязательны `text`, `type`, роли `subject`, `actor`, `action`, `object` и необходимые значения типизированного actor. В `subject` хранится грамматический субъект; в итоговую SRL-разметку это поле не переносится.

Роли переводятся в обычные факты, после чего используется общий `render()`. `intention` и `operation` по умолчанию равны `none`, если явно не заданы в ролях.

### 12.2. Грамматические метаданные

Для этой библиотеки валидатор задаёт закрытые значения:

| Поле события | Допустимые значения |
| --- | --- |
| `tense` | `present`, `past`, `future`, `nonfinite` |
| `aspect` | `simple`, `continuous`, `perfect`, `perfect_continuous` |
| `voice` | `active`, `passive` |
| `polarity` | `positive`, `negative` |
| `form` | `finite`, `infinitive`, `gerund`, `participle` |
| Необязательный `status` | `asserted`, `habitual`, `intended`, `hypothetical`, `reported`, `inferred`, `required`, `possible`, `counterfactual` |

Не нужно переносить эту таблицу на основной корпус как его полный словарь значений. В книге встречаются, например, дополнительные статусы `planned`, `conditional`, `unwanted` и другие; общий валидатор не ограничивает их этим списком.

Метаданные события `form` не проецируются в итоговый факт. Если же поле `form` уже находится непосредственно в факте основного корпуса, общий рендерер может его вывести. Аналогично, метаданные `features`, `parent`, `relation` и `context` не становятся автоматически обучающими вопросами дополнительного набора.

### 12.3. Parent, relation и context

`parent` ссылается на более ранний predicate в том же предложении и считается с единицы. При наличии `parent` требуется `relation`, и наоборот.

`context` — список номеров более ранних предложений внутри данного примера, тоже с единицы. Эти метаданные не совпадают с нулевыми индексами `embedded_roles` и не являются номерами строк выходного `.txt`.

Они проверяются как структурные связи. Текстовые опоры в готовой story всё равно рассчитываются общим рендерером после объединения предложений и переноса координат.

### 12.4. Multi-sentence и combine

Многопредложный шаблон заранее содержит все свои предложения и разметку. Их тексты соединяются одним пробелом и образуют одну строку входа.

При `combine: true` однопредложный шаблон дополнительно создаёт пары собственных экземпляров с различающимися значениями участников. Пары с одинаковым участником или участником `unknown`/`user` пропускаются. Программа сравнивает значения участников, например `Mary` и `John`, а не общий тип `person`.

`combine` не разрешён для шаблона, который уже содержит несколько предложений. Это не генерация диалога: роли и контекст новых предложений не придумываются.

Уроки повторения могут включать шаблоны более ранних уроков через `review_units`; ссылки на текущий или более поздний урок запрещены.

### 12.5. Различие в гранулярности намерений

Общий выходной формат не означает одинаковый смысловой разбор всех конструкций в двух библиотеках.

В основном корпусе `I want to give ...` может быть одним фактом целевого действия. Дополнительный шаблон `Mary wants to read the book.` содержит отдельные события `want` и `read`, а вложенное действие связано с родительским.

Генератор не унифицирует эти представления автоматически. При расширении данных нужно учитывать выбранную гранулярность и не считать любой текстово похожий пример эквивалентным по фактам.

## 13. Дубли, выборки и статистика

Все разрешённые сочетания кандидатов перебираются детерминированно. Случайного сэмплирования и добора до заданного количества stories нет.

Для поиска дублей используется входной текст с `casefold()` и нормализацией пробелов. Одинаковые входы с согласованной разметкой дают одну story. Конфликтующие ответы или разные итоговые stories при одинаковом ключе входа вызывают ошибку, а не случайный выбор варианта.

Семейства совпавших примеров объединяются. Выборка определяется SHA-256 имени итогового семейства: первые восемь байтов интерпретируются как целое, остаток по модулю 100 выбирает `valid` для 0–9, `test` для 10–19 и `train` для 20–99.

Это примерно 80/10/10 по семействам, а не гарантия точных процентов по числу stories. Связанные варианты одной семьи остаются вместе. Изменение семейства может изменить выборку; одинаковые данные и порядок библиотеки дают повторяемый результат.

Число однофрагментных и многофрагментных примеров основного набора считается после удаления дублей по числу фактов: один факт — один фрагмент. Перекрывающиеся диапазоны тоже считаются отдельными фрагментами. Это не статистика количества предложений по пунктуации.

На момент описанной схемы основной корпус содержит 8 046 записей и 11 974 факта, из которых получается 12 231 уникальный вход; дополнительная библиотека даёт 933 уникальных примера. Эти числа описывают текущие данные, а не ограничения генератора.

Человеческие вопросы из `questions.json` наследуют выборку соответствующего основного примера. Для каждого исходного текста должна существовать запись вопросов или явное исключение; новые допустимые варианты требуют собственных проверенных вопросов. Полнота такого покрытия не доказывает, что перечислены все мыслимые человеческие вопросы.

<a id="corners"></a>

## 14. Пограничные случаи

| Случай | Принятое поведение | Ошибка, которой нужно избегать |
| --- | --- | --- |
| Несколько одинаковых `is` | У каждого факта свои spans | Привязывать все факты к первому `is` |
| Вопрос с инверсией | Вспомогательный и основной глаголы выбираются раздельно | Включать субъект в `predicate` |
| Общий субъект у двух сказуемых | Повторять смыслового участника, при необходимости со ссылкой на `1` | Дописывать субъект в исходный фрагмент |
| Общий вспомогательный глагол | Использовать его исходные координаты с явным фрагментом-владельцем | Считать повтор spans достаточным без текстового владельца |
| `turned it off` | `verb: turned off`, объект отдельно | Терять `off` или включать `it` в форму глагола |
| Оставшееся `to` | `predicate: to`, `verb: none`; смысл действия — из доступного контекста | Выдавать отсутствующий глагол за слово из текста |
| Отсутствующая связка | `predicate: none`, `verb: none`, возможен `action: be` | Вставлять `is` в spans |
| `Yes, she does.` отдельной story | `action: unknown` | Заимствовать действие из соседнего упражнения |
| `There is a picture ...` | `action: be`, `object: picture`, actor отсутствует | Нормализовать `is` в `exist` или делать `there` человеком |
| Пассив с `by Mary` | `person: Mary`, объект — пациент | Делать подлежащее исполнителем |
| Пассив без исполнителя | Неизвестный actor | Подставлять автора из активного варианта упражнения |
| `The car needs washing.` | Смысл вложенного действия учитывает пассивную роль автомобиля | Считать автомобиль исполнителем мытья по форме герундия |
| Каузативное `had her car repaired` | Разделять организатора и неизвестного исполнителя ремонта | Приписывать ремонт самому заказчику |
| Возвратное `myself` | Связать нужную роль с участником и указать `reflexive` | Всегда превращать `myself` в отдельное имя |
| Усилительное `yourself` | Сохранять объект и отдельно указывать усиление | Делать любое `self` возвратным объектом |
| `by himself` и `each other` | Самостоятельность и взаимность разбираются по смыслу | Считать их одним вариантом возвратности |
| Прямая речь | Учитывать явного говорящего и адресата внутри входа | Любое цитируемое `you` связывать с внешним пользователем |
| Косвенный вопрос с `if` | Сохранять `non_question` у повествовательной реплики | Создавать условие только из-за слова `if` |
| Контрфактическое условие | Сохранять модальность и статус события | Добавлять противоположное событие как будто оно явно утверждено |
| `take ... to water ...` | Разделить отношение длительности и действие; использовать явную связь события | Выдавать `watering ...` за человека или оставлять длинный actor в компактном выводе |
| Вложенное `I have` внутри `The computer ...` | Допустить вложенный диапазон внутри внешнего | Насильно делать все фрагменты непересекающимися |
| Повтор `to pay` в разных клаузах | Различать контексты и координаты | Переносить объект или статус между повторами без основания |
| `time: spring` и `when: after autumn` | Сохранить обе роли | Перезаписать участника обстоятельством |
| `location: Newcastle` и `where: ...` | Сохранить место-участника и его положение | Смешать две функции одного типа сущности |
| Разные типы кандидатов | Разделить явные схемы, сохранив общее семейство при необходимости | Превратить `cities` или `sheep` в `person` |
| `purpose` при занятом объекте | Сохранить объект; отдельное действие разобрать отдельно | Заменить `book` на `present` только ради удаления `purpose` |

Сложные конструкции не следует размечать по одной таблице замен. Для них проверяют весь вход, согласованность фактов и существующие примеры соответствующего урока.

## 15. Проверки и ограничения

### 15.1. Что проверяет код

- Уникальность ключей JSON и идентификаторов, версии схем, корректность уроков и покрытия.
- Формат исходных английских текстов и строковых значений фактов.
- Обязательные поля, сочетание actor с полем его значения, допустимые `type` и `operation`.
- Отсутствие запрещённых `purpose` и `status: questioned`.
- Форму и границы spans, отсутствие пробелов по краям выбранных частей, соответствие `predicate` исходному тексту.
- Совпадение числа фактов и наборов spans.
- Недопустимость разрезания слова, сокращения или дефисного слова границей фрагмента.
- Принадлежность `verb` предикату и наличие текстового владельца для общих частей.
- Сохранение выбранной многословной части `action` в поверхностном `verb`, с исключениями для эллипсиса и дефисного причастия; наличие ключевых компонентов явно заданных составных модальностей в `predicate`.
- Структуру связей `embedded_roles`, а в дополнительной библиотеке — `parent`, `relation` и `context`.
- Восстановление исходного варианта шаблона и его совпадение с ручной записью.
- Допустимость слотов и комбинаций, непротиворечивость дублей, корректность номеров и ссылок в stories.
- Покрытие основного корпуса человеческими вопросами или явными исключениями.

### 15.2. Что остаётся ручной ответственностью

Валидатор не доказывает, что выбрана лучшая граница клаузы, что человек верно разрешил местоимение, что роль семантически точна или что новая комбинация звучит естественно.

В частности, он не считает все смысловые глаголы и не требует отдельного факта для каждого из них; не устанавливает истинность утверждения; не проверяет лексическую природу каждого phrasal verb; не выводит категории участников по миру или по словарю имён.

Различие «структурно допустимо» и «правильно размечено по смыслу» нужно сохранять при ревью. Новый пограничный случай требует проверки конкретного примера, даже если он успешно проходит общую валидацию.

### 15.3. Сборка и обучение — разные этапы

Генератор создаёт текстовые stories. Он не задаёт токенизацию, attention mask, `labels=-100`, порядок подачи фрагментов в модель или функцию потерь.

Если модель должна видеть весь вход, но обучаться только на определённых ответах, это необходимо отдельно реализовать в загрузчике и тренировочном коде. Номера опорных строк сами по себе не являются маской внимания и не обеспечивают понимание скрытых состояний.

## 16. Как добавлять и исправлять разметку

### 16.1. Основной корпус

1. Подготовить полный английский вход и определить факты по принятой для конструкции гранулярности.
2. Для каждого факта определить смыслового участника, его тип при наличии согласованной категории, действие, роли, полярность и вопросительность.
3. Записать `predicate`, выбрать `predicate_spans`, `verb_spans` и один непрерывный `fragment_spans` на факт.
4. Проверить эллипсис, общий контекст, отрицание, цитаты, возвратность и вложенные действия. Добавить `embedded_roles` только для действительно отдельно представленного события.
5. Добавить запись в `sentences.json` с уникальным `id` и корректным уроком.
6. Для существующего примера согласованно изменить его `fact_templates.json`. Для нового примера сборщик может создать фиксированный шаблон без слотов.
7. Если нужны варианты, явно задать слоты, формы и ограничения; проверить все связанные роли и типы участников.
8. Обновить `questions.json`: исходные вопросы, варианты или явное исключение должны соответствовать новому покрытию и тексту.
9. Запустить обычную сборку и проверить конкретные выходные stories.

Синхронизация сохраняет существующие переменные шаблоны, удаляет шаблоны исчезнувших записей и создаёт фиксированные шаблоны новых. Она не переписывает устаревшие ручные ответы существующего шаблона по догадке. Несогласованное изменение исходного факта вызывает ошибку.

### 16.2. Дополнительная библиотека

Изменения вносятся в `templates.json` и, при необходимости, `nouns.json`/`verbs.json`. Нужно учитывать типы всех кандидатов, spans в строке с placeholders, грамматические метаданные и исходные номера `parent`/`context`.

Для вариантов одного смыслового шаблона сохраняется общее `family`. Пример множественного числа с людьми и городами показывает, как разнести типы, не разделяя связанные примеры между train/valid/test.

### 16.3. Проверка изменения

```shell
python -m unittest discover -s tests -p "*book*.py"
python build_book_srl.py
```

Для новой сложной конструкции полезен регрессионный тест, который проверяет ожидаемые роли, точные фрагменты и ссылки. Проверка только успешного запуска не обнаружит смысловую ошибку.

Готовые `.txt` — результат генерации. Правку нужно делать в исходном JSON или коде общего правила, иначе следующая сборка заменит ручное исправление файла результата.

### 16.4. Частые причины ошибки сборки

| Ошибка | Что проверить |
| --- | --- |
| Тип actor не соответствует полю значения | Наличие нужного `person`/`time`/`location`/`organization`; обстоятельства должны быть в `when`/`where` |
| `predicate` не совпадает с spans | Точные символы, регистр, апострофы, координаты повторяющегося слова |
| Граница разрезает слово или placeholder | Разделение атрибутов слота и координаты исходной строки шаблона |
| Часть предиката не имеет владельца | Фрагмент, который действительно содержит общий вспомогательный глагол или другую часть |
| Фрагмент исключает свой глагол или частицу | Полный набор `verb_spans`, особенно у разделённых фразовых глаголов |
| Шаблон отличается от ручной записи | Согласованность `sentences.json`, исходных bindings и фактов/spans шаблона |
| Конфликт одинаковых входов | Разные факты, границы, значения или порядок вывода для одного нормализованного текста |
| Не хватает вопросов к варианту | Новые bindings и точный текст в `questions.json` |
| Пустой или неподготовленный урок | Покрытие всех уроков и непустые наборы шаблонов |

Проверки разметки выполняются до записи результатов. Это защита от сохранения заведомо противоречивого датасета, а не автоматическое исправление его смысла.
